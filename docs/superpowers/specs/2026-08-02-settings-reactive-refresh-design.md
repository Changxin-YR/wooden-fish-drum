# 设置实时响应式刷新设计

## 背景

设置页在修改音量、自定义文字等实时数据后，持久化数据会变化，但当前页面的数值或状态不会稳定地立即刷新。根因是运行时直接修改 `AppStore.settings` 的字段，而 ArkUI 页面依赖的是 `Index` 中的 `@State settings`。对象内部字段原地变化不会产生新的响应式对象引用，子页面因此可能继续显示旧快照。

## 目标

- 设置页所有可变项在用户操作后立即显示最新值或选中状态。
- 首页及其他依赖设置的页面在切换后读取同一份最新设置。
- 本地持久化保持异步，不阻塞控件反馈。
- 持久化失败时保留当前内存状态，并显示已有的本地存储异常提示。
- 不引入网络、后端或新的全局状态框架。

## 非目标

- 不改动设置项的业务含义、默认值或持久化格式。
- 不重构整个应用为 `AppStorage` 或新的状态管理架构。
- 不调整页面布局与视觉样式。

## 方案

采用父页面持有唯一响应式设置快照的方案。

`AppStore.settings` 继续作为业务与持久化层的可变设置对象。`Index.settings` 作为 ArkUI 渲染层快照，每次设置发生变化后都从 `AppStore.settings` 创建一个新的 `AppSettings` 对象并赋值。新对象引用触发 `@State` 更新，并向 `SettingsPage`、`HomePage` 等子页面传播。

设置页仅保留确有编辑过程的局部状态：

- 音量滑块使用局部 `@State` 跟随拖动，保证滑块与百分比每一帧同步；同时更新内存设置和父页面快照，在拖动结束或点击轨道时持久化。
- 自定义文字编辑框使用局部草稿；保存后立即更新行内摘要和父页面快照，再等待持久化结果。
- 开关、音色和主题不维护重复局部副本，直接由父页面设置快照驱动。

## 数据流

1. 用户操作设置控件。
2. 回调立即修改 `AppStore.settings`。
3. `Index` 立即复制设置并赋给 `@State settings`。
4. ArkUI 重新渲染当前设置页及其他设置消费者。
5. 持久化异步执行。
6. 保存失败时设置 `storageError`，展示错误提示；不静默回滚用户刚完成的界面操作。

音量拖动是唯一高频路径。拖动事件每次更新局部数值和内存快照，只在 `SliderChangeMode.End` 或 `SliderChangeMode.Click` 时写入 Preferences，避免连续磁盘写入。

## 组件边界

- `Index`：负责设置变更编排、创建响应式快照、处理保存失败。
- `SettingsPage`：负责控件交互和编辑草稿，不直接访问存储。
- `AppStore`：负责业务设置对象及持久化调用。
- `SettingsRepository`：负责串行写入设置快照，避免快速连续保存乱序覆盖。

## 异常处理

- 设置写入失败返回 `false`，由 `Index` 将 `storageError` 置为 `true`。
- UI 保持用户刚选择的值，使运行期行为和界面一致。
- 应用重启后以最后一次成功保存的设置为准。

## 测试与验收

- 先增加失败测试，证明连续设置修改会保存最新快照，且设置复制生成独立对象。
- 验证音量拖动后百分比、滑块位置和运行时音量同步。
- 验证音效、振动、浮动文字、音色、主题和自定义文字操作后立即显示最新状态。
- 验证自定义文字保存后，设置页摘要与首页文案均读取新值。
- 执行项目静态检查、Hypium、debug/release 构建。
- 在可用 phone 设备或模拟器上完成设置页交互验证；tablet 与 2in1 在无设备时明确记录为 `blocked`。

## 影响范围

预计仅修改设置响应式快照相关的页面编排、必要的设置复制辅助逻辑、对应 Hypium 测试，以及 `tasks.md`、`changes.md` 和 QA 记录。不会改变应用标识、签名身份或发布状态。

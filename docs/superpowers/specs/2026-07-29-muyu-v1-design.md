# 功德木鱼 HarmonyOS V1.0 设计规格

## 1. 决策摘要

- 产品名称：功德木鱼。
- 应用标识：`com.max.muyu`。
- 技术栈：HarmonyOS NEXT、Stage 模型、ArkTS、ArkUI、API 24、Hvigor modelVersion 6.0.0。
- 设备范围：`phone`、`tablet`、`2in1`。
- 工程方案：单一 `entry` 模块、原生 Navigation、Preferences、本地资源，无第三方运行时依赖。
- 视觉基准：手机模式选择页采用用户提供的高保真插画版截图；首页、统计和设置分别以用户提供的对应高保真截图为基准。
- 宽屏策略：平板采用居中双栏，2in1 采用主内容加固定操作栏；宽屏不拉伸手机插画、卡片和字号。
- 交付范围：连续完成 V1.0 五个阶段，每阶段通过类型检查和 debug 构建后再进入下一阶段。

## 2. 产品目标

构建一款纯单机、无登录、无网络权限、无广告和无付费能力的功德木鱼应用。用户首次启动选择程序员、僧侣或普通用户模式，之后可立即通过手动或自动敲击获得声音、动画、振动和文字反馈，并使用目标、限时、统计和本地设置功能。

三种用户模式不是账号或权限体系。它们共用页面、服务和数据，只提供不同的默认文案、主题、音色、推荐目标与入口排序。

## 3. 范围

### 3.1 V1.0 包含

- 首次启动模式选择及后续模式切换。
- 手动敲击、音效、振动、木鱼回弹和最多三条浮动文字。
- 今日次数、总次数、手动次数、自动次数和最近 7 天统计。
- 自定义文字、模式预设文字和恢复默认文字。
- 自由、目标、限时、自动四种会话模式。
- 音色、音量、振动、浮动文字和深浅色设置。
- 清除统计数据的二次确认。
- phone、tablet、2in1 响应式布局。

### 3.2 V1.0 不包含

AI、后端、网络请求、登录、云同步、广告、支付、会员、社区、排行榜、桌面卡片、手表端、成就、养成、呼吸训练、背景环境音和多设备协同均不实现，也不预埋运行时依赖。

## 4. 工程架构

### 4.1 模块与入口

- 根工程只包含 `entry` 模块。
- `EntryAbility` 初始化应用上下文、Preferences 与窗口主题。
- `pages/Index.ets` 是唯一 `@Entry` 页面，持有 `NavPathStack` 和应用级导航状态。
- 首次启动读取 `initialized`：未初始化显示 `ModeSelectPage`，已初始化显示 `HomePage`。
- `HomePage`、`StatsPage` 和 `SettingsPage` 共用底部导航；复杂操作使用 Dialog、Sheet 或页面内面板，不增加路由页面。

### 4.2 目录职责

```text
entry/src/main/ets/
├── entryability/         # Stage Ability 与应用生命周期
├── pages/                # Index、模式选择、首页、统计、设置
├── components/           # 模式卡、木鱼、浮动文字、底栏、柱图、确认弹窗
├── models/               # 枚举、设置、统计、会话和展示模型
├── constants/            # 模式配置、路由、文案和设计 Token
├── repositories/         # Preferences 读写与统计 JSON 持久化
├── services/             # 敲击、会话、音频、振动和统计编排
└── utils/                # 日期、数字和输入校验
```

页面只编排状态、生命周期与组件。Repository 不引用页面。Service 不持有 ArkUI 组件。组件通过强类型属性和回调通信，不直接访问 Preferences。

## 6. 用户模式配置

`USER_MODE_CONFIGS: Record<UserMode, UserModeConfig>` 是三种模式的唯一配置源。

| 模式 | 默认文字 | 默认主题 | 默认音色 | 推荐目标 | 功能顺序 |
| --- | --- | --- | --- | --- | --- |
| 程序员 | `Bug-1` | 深色 | 清脆 | 10、30、60、108 | 自由、限时、目标、自动 |
| 僧侣 | `功德+1` | 浅色 | 低沉 | 18、36、54、108 | 自由、自动、限时、目标 |
| 普通用户 | `好运+1` | 浅色 | 柔和 | 10、30、50、100 | 自由、目标、限时、自动 |

僧侣模式规格中的“呼吸节奏”不在 V1.0 实现，因此其第四入口使用已在 V1.0 范围内的目标模式，不展示未实现入口。

## 7. 页面与视觉设计

### 7.1 全局视觉系统

- 风格：东方极简、温暖、安静、现代。
- 浅色：背景 `#F6F1E8`、卡片 `#FFFDF8`、主文字 `#2E2924`、次文字 `#817970`、木色 `#8A5635`、点缀 `#A9824B`。
- 深色：背景 `#171513`、卡片 `#24211E`、主文字 `#F1ECE4`、次文字 `#AAA198`、木色 `#99613E`、点缀 `#C29961`。
- 字体使用 HarmonyOS Sans / 系统中文字体；标题、正文、辅助文字分别使用统一 Token，不按窗口宽度缩放字号。
- 卡片圆角不超过 8vp，交互控件最小点击区域 48vp。
- 动效为 150–220ms，遵循系统减少动态效果设置。
- 禁止大面积渐变、高饱和色、粒子、金币、爆炸、复杂宗教装饰和商城化视觉。

### 7.2 ModeSelectPage

- 手机以用户选定的高保真插画版为基准：顶部木鱼品牌区、莲花分隔、三张人物卡和底部棕色 CTA。
- 默认选中程序员，选中态同时使用边框、勾选图标和轻微背景变化，不只依赖颜色。
- 点击“开始使用”后保存完整模式默认设置，再替换导航根页面为首页，不能返回首次选择页。
- 平板将品牌区与模式卡区分为左右两栏；2in1 使用左侧品牌区、右侧模式选择区。

### 7.3 HomePage

- 页面包含顶部模式与今日计数、浮动文字层、木鱼主交互区、今日与累计数据、会话控制区和底部导航。
- 程序员模式默认采用高保真深色截图结构；僧侣和普通用户沿用同一布局，仅替换主题、素材、文案和入口顺序。
- 木鱼实际点击区域大于位图。每次有效点击触发一次计数、动画、音效、可选振动和可选浮动文字。
- 木鱼动画为 `100% -> 95% -> 102% -> 100%`，约 200ms，可重新开始且不阻塞下一次点击。
- 浮动文字从木鱼上方向上移动并淡出，同时最多三条。

### 7.4 StatsPage

- 以高保真统计截图为基准，包含日/周/月/年分段控件、四项摘要、最近 7 天柱图、连续天数与 30 日趋势。
- V1.0 的周/月/年入口只切换已能从每日记录派生的汇总，不引入第三方图表库。
- 柱图使用 ArkUI 基础组件绘制，零数据时显示零值基线和明确空状态。

### 7.5 SettingsPage

- 以高保真设置截图为基准，分为用户模式、敲击反馈、外观和数据四组。
- 文字选择和自定义文字位于敲击反馈组；自定义文字去除首尾空白，最多 12 个汉字或等价 12 个 Unicode 字符。
- 清除所有统计必须二次确认。取消不修改数据；确认后清空统计但保留应用设置和模式选择。
- 隐私说明明确数据只保存在本机且无网络权限；关于页面信息使用弹窗展示，不新增独立页面。

### 7.6 素材策略

- 木鱼、人物和品牌素材优先从用户提供的原始高分辨率界面图裁切、清理和导出，不重新生成近似人物或近似木鱼。
- 系统语义图标优先使用 `SymbolGlyph`；缺失且需要严格匹配的图标从用户提供的图标板导出。
- 生产资源使用语义名称，保留原始设计图和裁切清单，避免后续无法追溯。
- 木鱼音频使用随包内置的低沉、清脆、柔和短 WAV，不请求网络资源。

## 8. 多设备策略

布局按可用窗口宽度和设备类型派生：

- Compact：宽度小于 600vp，phone 单栏，底部导航固定在安全区上方。
- Medium：600–1023vp，tablet 居中双栏，内容最大宽度受控。
- Expanded：1024vp 及以上，2in1 使用主内容与固定操作栏分栏。

组件皮肤、字体层级、图标、圆角和素材比例跨设备一致。宽屏增加留白和列数，不按比例放大手机页面。窗口变化时重新计算布局，所有页面避让状态栏、导航栏和窗口安全区。长中文、系统大字体、横屏和窗口缩放不得造成文字与按钮重叠。

手机按参考图做高保真验收；平板和 2in1 因没有对应像素稿，以同一设计系统、信息层级、无拉伸和无重叠作为验收标准。

## 9. 本地数据与数据流

### 9.1 SettingsRepository

- 使用 HarmonyOS Preferences 保存 `AppSettings` 字段。
- 默认值只在一个工厂函数中定义。
- `initialized` 为 `false` 时进入模式选择；选择后一次性保存模式默认值和初始化状态。
- 模式切换保留统计、自定义文字和用户手动主题。当前文字属于旧模式预设时替换为新默认文字；属于自定义文字时保留。

### 9.2 StatsRepository

- 每日记录使用日期键 `YYYY-MM-DD`。
- 原始 `DailyRecord[]` 是统计唯一事实源；今日、总计、手动、自动和趋势均从记录派生。
- 手动敲击先同步更新内存状态，每累计 5 次落盘一次。
- 页面隐藏、应用进入后台、自动模式停止和服务销毁前强制刷新持久化。
- 每次读取今日记录先比较本地日期；跨日保留历史并创建零值新记录。

### 9.3 会话与敲击流

1. 页面把用户动作交给 `SessionService`。
2. `SessionService` 判断会话状态并产生一次有效敲击。
3. `StatsService` 更新内存记录和页面显示模型。
4. `AudioService`、`VibrationService` 和 UI 动画各自消费同一次敲击事件。
5. 达到落盘条件时由 Repository 保存。

自由、目标、限时和自动模式互斥。目标达到后自动停止并显示页面内完成提示。限时结束显示本次时长和次数。自动模式支持开始、暂停、继续、停止及 0.5、1、1.5、2 秒间隔；重复开始不创建第二个定时器。

进入后台或页面销毁时停止自动敲击和倒计时、清理定时器并刷新数据。会话状态不跨应用重启恢复。

## 10. 异常处理

- Preferences 读取失败：使用安全默认值，保留应用可操作性并显示轻量提示。
- Preferences 写入失败：保留内存状态，记录非敏感错误，在下一生命周期刷新点重试。
- 统计 JSON 无法解析：不让页面崩溃；返回空显示模型并记录错误，避免把无效内容当成有效统计。
- 音频资源加载或播放失败：计数、动画和振动继续执行，音频失败不回滚有效敲击。
- 振动能力不可用或被拒绝：静默降级为无振动，其他反馈继续。
- 定时器启动失败或状态不一致：回到停止状态并保留已完成计数。
- 所有日志不得包含签名秘密、用户隐私或完整 Preferences 内容。

## 11. 无障碍与易用性

- 木鱼、模式卡、底部导航、开关和图标按钮提供语义标签。
- 选中态同时使用形状、图标或文字，不只使用颜色。
- 主操作触控区域至少 48vp；木鱼点击区域大于可见木鱼。
- 文本支持系统字体放大，必要时换行或省略，不能遮挡相邻内容。
- 深浅色均检查文字、边框、图标和图片背景对比度。
- 减少动态效果开启时缩短或取消位移动画，保留必要的状态变化。

## 12. 测试与阶段门禁

### 阶段一：基础工程

- 验证首次启动进入模式选择。
- 选择后进入首页且无法返回选择页。
- 重新启动直接进入首页。
- 验证三种模式配置和设置持久化。

### 阶段二：木鱼核心体验

- 连续快速敲击 100 次，计数必须为 100。
- 每次敲击产生一次动画、一次音频请求、可选振动和最多三条浮动文字。
- 音频失败不影响计数。

### 阶段三：设置与模式切换

- 模式切换立即刷新视觉和默认配置。
- 历史统计、自定义文字和手动主题不丢失。
- 自定义文字长度、空白和恢复默认规则正确。

### 阶段四：自动、目标和限时

- 重复开始不产生重复定时器。
- 目标在准确次数停止。
- 限时结束结果准确。
- 应用进入后台后自动和计时立即停止。

### 阶段五：统计与清除

- 今日、总计、手动、自动和最近 7 天派生正确。
- 跨日数据保留且今日归零。
- 清除操作必须二次确认，确认后统计归零、设置保留。

纯逻辑和 Repository 采用 Hypium 测试，遵循先失败、后实现、再重构。每阶段执行 ArkTS 类型检查和 debug Hvigor 构建。最终执行标准化检查、完整测试、debug/release 构建并记录 HAP 路径与大小。

设备交互验证分别记录 phone、tablet、2in1。没有相应模拟器或真机时标记 `blocked` 并写明恢复条件，不以设计稿、预览器或推测替代真机结果。

## 13. 完成定义

- 标准项目文档、Stage 配置、路由、源码和资源完整。
- ArkTS 无类型错误且不使用 `any`。
- 不声明网络权限，不包含网络、广告、支付、登录或云依赖。
- Hypium 测试通过，debug 和 release 构建退出码为 0，HAP 真实存在且非空。
- 需求范围内的主路径和异常降级已验证。
- 手机视觉与指定截图对照完成；平板和 2in1 的布局、窗口变化与安全区完成设备级验证或如实标记阻塞。

# 浮动提示冒泡堆叠设计

## 目标

优化首页快速连续敲击时的浮动文字提示。提示应从固定锚点向上堆叠，避免新增提示继续向下占用空间并遮挡木鱼主体。

## 根因

`WoodenFishView` 当前使用普通 `Column` 从上到下渲染 `floatingTexts`。数组按旧到新追加，快速点击时最多三条提示依次向下扩展，第三条进入木鱼主体区域，造成明显遮挡。

## 已确认方案

采用方案 A：底部锚定的冒泡堆叠。

- 同时最多显示 3 条提示，保持现有限制。
- 最新提示固定在木鱼组件顶部中心的 `y: 8vp` 锚点。
- 更早的提示依次排列在最新提示上方，不允许向木鱼方向继续向下扩展。
- 相邻提示的垂直间距为 48vp；三条提示从新到旧的透明度依次为 `1`、`0.76`、`0.52`。
- 保持现有提示文案、圆角、主题颜色和 760ms 自动清理时长。
- 普通敲击提示与目标完成后的“功德圆满”提示使用同一套堆叠规则。

## 组件与数据流

修改范围限定在 `entry/src/main/ets/components/WoodenFishView.ets`。

`floatingTexts` 继续按时间顺序保存，新增提示仍追加到数组末尾，数组仍裁剪为最后 3 条。渲染层以数组末尾为最新条目：最新条目保持 `y: 8vp`，前一条相对上移 48vp，最旧一条相对上移 96vp。渲染时根据条目在当前数组中的新旧位置设置透明度，数据结构不增加仅用于布局的状态。

提示层不参与点击处理，不改变 `WoodenFishView` 整体点击区域。木锤、木鱼图片、波纹动画、敲击计数和声音反馈不在本次修改范围内。

## 快速点击行为

用户连续点击 1 至 3 次时，提示从固定锚点向上累积，最新提示始终在最下方。第 4 次及后续点击只保留最近 3 条，最旧条目被移除，其余条目向上重排。每条提示到达 760ms 生命周期后按现有定时清理逻辑移除，不得遗留空白占位或改变组件高度。

## 响应式与主题

提示层使用 vp 尺寸和组件内部定位，在 phone、tablet、2in1 上沿用同一相对锚点。浅色和深色主题继续使用现有文字色及背景色。提示内容较长时沿用当前单行文本表现，组件不得因提示出现而改变整体高度。

## 验证标准

- 连续快速点击至少 5 次时，屏幕上同时最多出现 3 条提示。
- 最新提示位于最下方，旧提示依次向上排列且透明度逐级降低。
- 三条提示均不遮挡木鱼主体，也不与右上角当前文字计数产生不合理重叠。
- 提示出现和消失不会推动木鱼、木锤或页面其他组件发生位移。
- 停止点击后，所有提示在各自 760ms 生命周期结束后正常清除。
- “功德圆满”提示遵循相同堆叠和清理规则。
- ArkTS 静态检查、布局回归检查、Hypium、debug、ohosTest 和 release 构建通过。
- 在可用 phone 模拟器上完成快速点击截图和交互验证；无可用 tablet、2in1 时如实标记为 `blocked`。

# 连续天数与会话快照修复设计

## 目标

修复用户当天尚未敲击时连续天数错误显示为 0 的问题，并统一 `SessionState` 的 UI 快照创建方式，避免新增状态字段后页面漏同步。

## 范围

- 调整 `StatsRepository` 的连续天数计算口径。
- 为 `SessionState` 提供返回独立副本的统一快照方法。
- 让 `Index` 通过该方法刷新会话状态。
- 增加对应 Hypium 回归测试。
- 不改变自动模式重复点击关闭、自动模式忽略手动点击、目标模式和计时器生命周期行为。

## 连续天数口径

若今天已有至少一次敲击，连续天数从今天开始向前计算。若今天尚无敲击，则从昨天开始向前计算，显示截至昨天仍然有效的连续记录。遇到首个无有效记录的日期立即停止，不跨断档累计。

示例：前天和昨天有记录、今天无记录时结果为 2；今天补敲后结果为 3；昨天无记录且今天无记录时结果为 0。

## 会话状态快照

`SessionState` 提供显式快照方法，创建新的 `SessionState` 并复制全部字段。调用方获得独立对象，后续修改服务中的源状态不会反向改变已经交给 ArkUI 的快照。

`Index.refreshSessionState()` 只负责获取该快照并赋给 `@State`，不再逐字段维护复制清单。以后新增会话字段时，只需更新模型内部的快照实现与模型测试。

## 测试与验收

- 连续记录延续至昨天且今天无记录时，返回截至昨天的连续天数。
- 今天有记录时，连续天数包含今天。
- 昨天断档且今天无记录时返回 0。
- 会话快照包含现有全部字段，且与源对象引用独立。
- 原有会话、统计和持久化测试继续通过。
- 执行静态检查、Hypium、debug/ohosTest/release 构建；设备不可用时明确记录阻塞，不以构建代替设备验证。

# 冷启动图标闪现优化设计

## 问题

HarmonyOS 冷启动时先依据 `EntryAbility.startWindowIcon` 绘制系统启动窗口。ArkUI 首帧接管后，`Index` 在 `ready=false` 阶段再次绘制同一应用图标，并等待本地数据、统计数据和音频资源全部初始化。木鱼图标中的木槌在短暂缩放显示时容易被误认为放大镜，重复绘制又放大了闪烁感。

## 已批准方案

- 保留系统启动窗口及现有桌面应用图标，避免冷启动白屏和无品牌反馈。
- `Index` 加载阶段只绘制与首页一致的背景，不显示应用图标、进度环或加载文字。
- Preferences 与 `AppStore` 仍是首屏必要数据，完成同步后立即设置 `ready=true`。
- `AudioService` 属于非关键能力，在首屏状态切换后异步初始化；初始化失败继续沿用既有静默降级行为。
- 音频池和音效 ID 作为一个候选资源包加载，通过初始化世代验证后才发布；页面释放或后续初始化会使旧候选失效并负责释放。
- 不修改包名、版本、签名、权限和业务数据模型。

## 回归验证

- 静态检查确认系统启动窗配置仍存在、`Index` 不再绘制 `app_icon`、音频初始化不再被 `await`。
- 执行项目标准检查、Hypium、debug/release 构建。
- Hypium 覆盖旧候选丢弃、当前资源发布以及取消时取回当前资源的状态契约。
- 在可用 HarmonyOS 设备上强停后冷启动，连续采集启动帧，确认系统图标之后直接进入首页且没有应用内第二次图标。

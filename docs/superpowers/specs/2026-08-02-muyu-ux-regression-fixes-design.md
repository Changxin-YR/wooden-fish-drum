# 功德木鱼界面与状态同步修复设计

## 背景

当前 phone 界面存在首页背景断层、木槌位置偏低、首页标题未跟随自定义文字、趋势默认看不到最新周期、年趋势入口冗余、设置开关越界，以及音量和自定义文字不能即时刷新的问题。本次只修复这些回归，不改变应用的单机边界、包名、签名身份和主要信息架构。

## 目标

- 首页浅色背景与木鱼素材区域保持连续，不出现明显色块断层。
- 木槌上移到木鱼敲击面的合理位置，原有敲击动画继续有效。
- 首页右上角显示当前自定义文字及其独立计数，例如“今日好运 0”。
- 自定义文字发生变化时，该首页计数从 0 重新开始；当天统计总数不清空。
- 日、周、月趋势按时间从早到晚排列，首次打开时优先显示今日、本周、本月；用户向右拖动查看更早数据。
- 移除年趋势入口和不再使用的年聚合分支。
- 保持设置卡片当前布局，仅将三个开关左移并约束在白色卡片内部。
- 音量和自定义文字修改后立即刷新当前页面，再异步持久化。

## 首页视觉

浅色首页使用统一的共享背景色。木鱼图片容器和素材外围底色统一到该颜色，保留水墨圆环、木鱼主体和阴影，不改变素材比例。首页根容器覆盖完整内容区域，避免父子容器或系统安全区露出不同底色。

木槌继续作为 `WoodenFishView` 中的独立 ArkUI 图层，仅调整静止基准位置。敲击时的旋转和位移动画仍相对于新的基准位置执行，槌头在静止状态靠近木鱼右下方敲击面，不遮挡主体关键轮廓。

## 首页文字计数

首页标题不再硬编码“今日功德”，改为 `settings.currentText`。首页显示计数与统计页的今日总数分离：

- 统计仓库继续记录当天全部手动和自动敲击，历史数据不因文字变化而删除。
- 设置保存当前文字对应的计数基线和基线日期。
- 首页计数等于“今日统计总数减去当前文字基线”。
- 更换为不同文字时，将基线更新为当时的今日总数，因此新文字立即显示 0。
- 同一天切换页面或重启应用后继续显示该文字的计数；跨天时基线自动失效，新一天从 0 开始。
- 重复保存同一个文字不重置计数。

该设计不为每次敲击额外写一份设置，只复用现有统计写入，并在文字变化时持久化一次基线。

## 趋势浏览

统计页只保留 `DAY`、`WEEK`、`MONTH` 三个切换项。每种趋势内部的数据顺序仍为从早到晚：过去数据在左，当前周期在右。

图表使用固定桶宽的水平滚动区域。页面首次出现、切换周期或数据刷新后，滚动位置定位到末端，使今日、本周、本月位于默认视口中。用户手指向右拖动时可回看左侧更早的数据。日、周、月分别沿用当前 7 日、8 周、12 月的数据范围，不新增无限历史加载。

当前周期标签保持明确：日显示今日日期，周显示包含今天的本周范围，月显示本月。删除年按钮、年标题和年桶生成逻辑，枚举可保留兼容值时仅用于旧数据解析，不再进入页面业务分支。

## 设置页即时刷新与开关约束

设置页继续使用现有卡片、行距、图标和开关样式。三个带开关的行增加右侧内边距，并给文字区域明确的可收缩宽度；开关设置固定宽度并向左偏移，确保 phone 宽度下完整落在卡片边框内，不改变其他行的排列。

音量拖动分为两步：

1. 每次 `onChange` 先更新页面使用的响应式 `settings` 副本，因此百分比即时变化。
2. 仅在拖动结束或点击轨道结束时写入 Preferences，避免连续高频持久化。

自定义文字保存同样先更新页面状态和首页计数基线，再异步写入 Preferences。保存失败时保留当前界面状态并显示现有存储异常提示，不让页面回退到旧值。

## 数据流

`SettingsPage` 发出值变化 -> `Index` 立即复制并替换 `@State settings` -> 当前页面重新渲染 -> `AppStore` 更新内存设置 -> Repository 异步持久化。

敲击事件仍由 `SessionService` 发出 -> `AppStore.recordHit` 更新统计 -> `Index.syncFromStore` 刷新汇总 -> 首页根据汇总与文字基线派生当前文字计数。

趋势仍由 `StatsPeriodService` 生成有序桶，`StatsBarChart` 只负责固定宽度渲染和最新周期初始定位。

## 测试与验收

### Hypium

- 更换为不同自定义文字后首页派生计数为 0，原今日统计不变。
- 同一文字重复保存不重置计数。
- 新敲击同时增加统计总数和当前文字首页计数。
- 跨天后首页文字计数从 0 开始。
- 日、周、月桶按时间升序，最后一个桶分别包含今日、本周、本月。
- 页面可用周期仅包含日、周、月。

# 静心木鱼 HarmonyOS V2.1 设计规格

## 1. 文档地位

本规格经用户于 2026-07-31 批准，是现有项目下一阶段改造的权威产品与技术基线。它在冲突处取代以下旧规格：

- `2026-07-29-muyu-v1-design.md`
- `2026-07-30-muyu-feedback-redesign.md`

未被本规格改变的工程约束、质量门禁和已验证实现继续有效。项目在现有工程上增量改造，不重新创建工程，不修改包名 `com.max.muyu`，不擅自修改签名身份或发布版本状态。

## 2. 决策摘要

- 产品展示名：静心木鱼。仓库名和包名保持不变。
- 产品定位：纯单机的木鱼节律、念珠计数和静心计时工具。
- 技术栈：HarmonyOS 6.1.1 API 24、Stage 模型、ArkTS、ArkUI。
- 设备范围：phone、tablet、2in1。
- 一级导航：练习、记录、设置。
- 核心工具：木鱼、念珠、一炷香。
- 首次启动：恢复两步引导，依次选择场景模式和默认工具。
- 场景模式：程序员模式、静心模式、日常模式，只改变默认配置，不产生账号或身份体系。
- 商业与数据边界：无网络、账号、广告、支付、排行、活动、云同步或第三方统计 SDK。
- 视觉基准：用户提供的三张 V2 页面稿作为 phone 高保真目标；使用 ArkUI 原生组件重建，不把整页截图当作页面背景。
- 实施范围：V2.1 完成三工具、三导航、场景引导、练习记录、基础设置及合规页面；扩展背景音、数据导出、里程碑和练习详情延后到 V2.2。

## 3. 产品边界

### 3.1 V2.1 包含

- 两步首次引导和后续场景模式、默认工具修改。
- 木鱼手动计数与自动节律。
- 念珠点击或轻扫计数、逐珠反馈和 27/54/108 节点提示。
- 一炷香 5、10、15、20、30 分钟计时，以及暂停、继续、结束和完成记录。
- 音效、音量、振动、浮动文字、主题和减少动画设置。
- 今日概览、累计数据、连续天数、最近 7 天趋势、工具分类和真实练习历史。
- 隐私说明、用户须知、开源许可、关于应用和清除本地数据。
- 旧设置和每日统计的兼容迁移。
- phone、tablet、2in1 响应式布局和相应测试门禁。

### 3.2 V2.1 不包含

- 拼手速、限时点击、速度成绩、挑战、排行、PK、奖励经济或竞技文案。
- 登录、头像、后端、网络请求、广告、支付、会员、捐赠、云同步和在线活动。
- 后台持续自动敲击或后台播放。
- 用户导入音频、数据导出、个人里程碑、扩展背景音乐库和练习详情页。
- 对宗教功效、改运、消灾、祈福结果或医疗、心理治疗效果的承诺。

## 5. 场景模式与引导

### 5.1 场景模式

| 内部兼容值 | 展示名称 | 默认用途 |
| --- | --- | --- |
| `programmer` | 程序员模式 | 工作间隙、专注与放松 |
| `monk` | 静心模式 | 安静计数和静心计时 |
| `general` | 日常模式 | 日常节律和轻度放松 |

旧枚举值保留，避免破坏本地数据。界面不展示“僧侣”或“普通用户”，也不使用人物身份判断。场景模式只提供默认主题、反馈文字、音色和默认工具建议；用户后续修改的设置优先于场景默认值。

场景初始默认值固定如下：

| 场景 | 主题 | 音色 | 反馈文字 | 推荐工具 |
| --- | --- | --- | --- | --- |
| 程序员模式 | 深色 | 清脆 | `专注+1` | 木鱼 |
| 静心模式 | 浅色 | 低沉 | `静心+1` | 一炷香 |
| 日常模式 | 跟随系统 | 柔和 | `放松+1` | 木鱼 |

推荐工具只负责第二步引导的预选中，用户最终选择始终覆盖推荐值。

### 5.2 两步首次引导

- 第一步显示三张场景卡，每张只包含原创图标、名称和一句用途说明，不使用宗教人物插画。
- 第二步显示木鱼、念珠、一炷香三个工具选项。
- 选中态同时使用边框、勾选符号和文字，不只依赖颜色。
- “开始使用”一次性保存 `initialized`、场景模式和默认工具，然后进入主界面。
- 升级用户不强制重新完成引导：根据旧 `userMode` 迁移场景；旧版本已统一为普通用户时迁移为日常模式，默认工具为木鱼。
- 设置页允许重新选择场景和默认工具，但不重放首次引导。

## 6. 页面与交互

### 6.1 练习页

phone 端以用户提供的 V2 练习稿为视觉目标，保留以下层级：

1. 产品标题与离线标识。
2. 今日概览：今日次数、累计次数、连续天数。
3. 木鱼、念珠、一炷香三段式工具选择。
4. 占据主要空间的练习画布。
5. 当前计数或剩余时间。
6. 工具专属控制区。
7. 音色、播放状态、音量和振动控制台。
8. 练习、记录、设置底部导航。

页面稿中的颜色、留白、木色、山水氛围和信息层级应高保真还原。实现必须同时满足：触控区域不小于 48vp、系统字体放大不遮挡、卡片不重复嵌套、横屏和宽屏不拉伸素材。稿件与这些要求冲突时，优先保证 HarmonyOS 可用性并记录视觉差异。

### 6.2 木鱼

- 整个木鱼可视区域及其外扩热区均可点击。
- 一次有效点击依次更新内存、页面、音效、振动、主体动画和浮动文字。
- 自动节律间隔为 0.5、0.8、1、1.5、2、3 秒，支持持续运行或 1、3、5、10、20 分钟。
- 自动节律支持开始、暂停、继续和结束；重复开始不能创建第二个定时器。
- 不再提供旧 `TARGET` 目标档入口。108 只可作为温和计数节点，不封顶、不计时、不形成挑战。

### 6.3 念珠

- 点击珠子或沿珠串方向轻扫产生一次计数，同一手势只能计数一次。
- 当前珠子具有形状或亮度反馈，并推进到下一珠。
- 27、54、108 次提供可选轻振动或提示音，不弹出竞技式完成页。
- 支持与木鱼相同的自动节律状态机。

### 6.4 一炷香

- 预设时长为 5、10、15、20、30 分钟。
- 开始后显示剩余时间和燃烧进度；暂停冻结展示；继续时从剩余时间恢复。
- 使用墙钟时间校正前后台恢复，避免定时器延迟造成重复或少计。
- 进入后台时保存开始时间、目标时长、累计暂停时长和当前状态；背景音暂停。
- 正常完成记录实际完成时长和 `completed=true`；用户提前结束记录实际时长和 `completed=false`。
- 点击香体只提供轻反馈，不增加次数。

### 6.5 记录页

phone 端以用户提供的 V2 记录稿为视觉目标。顶部提供今日、本周、本月、全部口径；内容包含摘要、最近练习、本地统计和趋势。

- 次数统计只汇总木鱼和念珠。
- 时长统计以所有练习会话的实际时长为准，一炷香单独展示。
- 工具占比不得把“次数”和“分钟”混合计算为同一百分比；界面使用“次数”和“时长”两个明确视图。
- 最近练习只展示真实 `PracticeSession`，不得生成示例数据。
- 旧版本每日汇总保留在趋势和累计值中，但不伪造为具体练习历史。

### 6.6 设置页

phone 端以用户提供的 V2 设置稿为视觉目标，按以下分组组织：

- 练习设置：默认工具、自动间隔、反馈开关。
- 音频设置：敲击音、敲击音量；V2.1 不承诺独立背景音乐库。
- 显示设置：系统/浅色/深色主题、跟随系统字体缩放、减少动画。
- 文字与触感：浮动文字、自定义文字、振动。
- 数据管理：清除今日数据、清除全部本地数据。
- 关于与合规：隐私说明、用户须知、开源许可、版本信息。

清除操作必须二次确认并说明不可恢复。清除今日只删除当天统计和当天练习历史；清除全部数据删除统计、历史和用户设置，随后回到首次引导。

## 7. 视觉资源策略

### 7.1 页面稿

三张 941 x 1672 RGB 页面图只作为 phone 对照稿，不进入 HAP 作为整页背景。状态栏、系统导航栏和时间由设备系统提供，不在 ArkUI 页面中绘制。

### 7.2 主体 PNG

三张 1024 x 1536 ARGB PNG 具有透明通道，但必须在入库前完成裁边、压缩和资源来源登记。

- 木鱼：当前图含烘焙发光点击圈。正式实现需要无光圈静止图；点击光圈由 ArkUI 独立绘制。若无法取得无光圈源图，不得通过粗糙修补冒充静止资源。
- 念珠：整图可作为基础层；逐珠反馈通过与图片尺寸绑定的强类型热点坐标和独立高亮层实现，不复制 108 张位图。
- 一炷香：正式实现应拆为底座/香体与烟雾层；燃烧进度通过遮罩或裁切控制，烟雾动效独立并可在“减少动画”时静止。

资源必须为用户原创、已购买商用授权或使用条款允许商用。`docs/ui/asset-manifest.md` 记录文件名、来源、授权、处理步骤和用途；无法证明授权的资源不得作为发布资源验收。

## 8. 状态与控制器

### 8.1 枚举

```typescript
export enum SceneMode {
  PROGRAMMER = 'programmer',
  MINDFUL = 'monk',
  DAILY = 'general'
}

export enum ToolType {
  WOODEN_FISH = 'wooden_fish',
  BEADS = 'beads',
  INCENSE = 'incense'
}

export enum PracticeStatus {
  IDLE = 'idle',
  RUNNING = 'running',
  PAUSED = 'paused',
  COMPLETED = 'completed'
}
```

旧 `UserMode` 和序列化值通过迁移层读取，业务页面只消费新的场景语义。不得使用 `any`。

### 8.2 单一活动任务

`PracticeController` 是活动练习的唯一真相源，组合工具状态和 `AutoRhythmController`。任何时刻最多存在一个自动节律或香计时任务。

- 切换工具时，空闲工具直接切换。
- 当前练习有未保存进度时先确认结束；确认后保存会话再切换。
- 切换一级页面时木鱼和念珠自动节律暂停并保存；香计时按时间戳保持可恢复状态。
- 页面销毁时释放定时器、动画监听和音频资源。

### 9.4 迁移规则

- 增加显式 `schemaVersion`，迁移必须可重复执行且不会重复累计。
- 旧 `manualCount` 和 `autoCount` 迁移到木鱼对应字段。
- 旧 `durationSeconds` 迁移到 `practiceSeconds`，来源不明确时不写入 `incenseSeconds`。
- 旧每日记录继续参与累计和趋势。
- 迁移不生成 `PracticeSession`；练习历史从升级后的第一次真实练习开始。
- 旧 `programmer/monk/general` 映射到三个场景模式；旧版本强制统一后的 `general` 映射到日常模式。
- 旧主题、音量、音色、振动、自定义文字和浮字开关在字段有效时保留。
- `TARGET` 运行状态不跨重启保存，无需迁移为活动任务。
- 解析或迁移失败时保留原始存储快照，应用使用安全默认值，并避免覆盖无法识别的数据。

### 9.5 会话边界

- 木鱼或念珠的第一次有效手动计数创建会话；连续交互归入同一会话。
- 手动会话在连续 60 秒无有效输入、切换工具、离开练习页或应用进入后台时结束。
- 自动节律从用户点击开始到主动结束或切换工具构成一次会话；前台内暂停、继续仍属于同一会话，暂停时长不计入练习时长。进入后台时提交当前会话，回到前台后由用户确认继续时创建新会话，避免把不确定的后台间隔计入时长。
- 一炷香从点击开始到正常完成或主动结束构成一次会话；暂停时间不计入 `durationSeconds`。
- 会话 `endTime`、次数和时长只在结束时最终写入；异常退出前使用生命周期保存点提交当前快照。
- 会话标识由本地开始时间和单调递增序号组成，不依赖网络或设备标识。
- 每个已提交会话只允许汇总到 `DailyStats` 一次，Repository 以会话标识保证幂等。

## 10. 持久化与性能

- 点击先同步更新内存，UI 不等待 Preferences 写入。
- Repository 使用串行写入队列，防止连续点击造成乱序覆盖。
- 木鱼和念珠按批次或短延迟节流落盘；进入后台、切换工具、结束练习和页面销毁前强制刷新。
- 音效播放器复用，单次点击不创建新播放器。
- 计时展示可按秒刷新，但实际时长以时间戳差值计算。
- 最近练习设置明确上限或分页读取，不能随历史增长把全部会话加载进首屏。

## 11. 生命周期与异常处理

- 冷启动、回前台和开始新练习前检查本地日期。
- 跨日创建新的 `DailyStats`，累计值和设置不清空。
- 木鱼、念珠自动节律进入后台默认暂停；回前台不自动继续，需用户确认继续。
- 一炷香按保存时间恢复准确剩余时长，完成事件最多记录一次。
- 音效或振动失败不能回滚有效计数。
- Preferences 写入失败时保留内存状态并在下一个安全刷新点重试；页面给出克制、可恢复的提示。
- 损坏 JSON 不导致崩溃，不把损坏数据静默覆盖为空。
- 主流程不得留下空页面、无响应按钮、不可关闭弹层或测试数据。

## 12. 多设备布局

- Compact `<600vp`：phone 单栏，按 V2 页面稿进行高保真验收。
- Medium `600-1023vp`：tablet 使用受控最大宽度和双栏重排；练习画布与控制设置分栏。
- Expanded `>=1024vp`：2in1 使用主练习区与固定信息/控制侧栏，底部导航可转为符合宽屏习惯的侧边一级导航。

宽屏只重排，不拉伸 phone 稿、位图或字号。窗口缩放、横屏、安全区和系统字体放大时不允许内容重叠。选中态必须同时具有非颜色信号，所有主触控目标不小于 48vp。

## 13. 隐私与合规

- 只保留目标 API 实际需要的振动权限；不申请网络、相机、麦克风、位置、账号或广泛文件权限。
- 隐私说明必须如实声明：无账号、无上传、无广告/统计 SDK，数据仅保存在本机并可由用户清除。
- 应用文案使用“节律、计数、放松、专注”等工具表达，不承诺宗教或健康功效。
- 开源许可页列出实际打包依赖及许可证；没有依赖时也不能虚构内容。
- 发布前另行核验正式签名、版本、AppGallery Connect 信息、备案、版权证明和隐私政策网址；开发阶段不擅自填写虚假材料。

## 14. 测试策略

业务行为严格先写失败测试，再写最小实现。测试至少覆盖：

- 设置和每日统计从旧 schema 到 V2.1 的幂等迁移。
- 木鱼、念珠手动与自动计数准确，快速输入不丢计数。
- 念珠一次手势只产生一次计数，27/54/108 节点只提示一次。
- 自动节律只有一个定时器，暂停、继续、结束和切工具状态正确。
- 香计时在暂停、前后台、跨秒延迟和重复恢复时不重复累计或重复完成。
- 日期变化后今日归零、累计保留。
- 练习会话和每日汇总保持一致。
- 清除今日与清除全部具有不同且正确的数据范围。
- 统计次数与时长使用独立单位，不混合计算比例。
- 大字体、减少动画、深浅色和非颜色选中态的组件级检查。

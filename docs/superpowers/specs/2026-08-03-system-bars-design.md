# 系统栏沉浸式配色设计

## 目标

在页面内容不进入状态栏和系统导航栏的前提下，消除系统栏与应用界面的颜色断层。覆盖首页、统计、设置、设置内隐私页，以及浅色、深色和跟随系统三种主题。

## 视觉规则

- 状态栏背景延续当前页面背景：浅色首页使用 `#FAF4EF`，浅色统计/设置/隐私页使用 `#F6F1E8`，深色页面使用 `#171513`。
- 系统导航栏背景延续应用底部导航栏：浅色使用 `#FFFDF8`，深色使用 `#24211E`。
- 浅色背景使用深色系统图标，深色背景使用浅色系统图标。
- 保持非全屏窗口布局，页面继续由系统安全区约束，内容不侵入系统栏。

## 架构

- `SystemBarStyleResolver` 是无副作用解析器，输入当前标签和最终深浅主题，输出明确类型的状态栏/导航栏颜色与图标模式。
- `WindowChromeService` 持有主窗口引用，初始化时显式关闭全屏布局，并将解析后的属性统一写入窗口。
- `EntryAbility` 在窗口创建时初始化服务；`Index` 在数据初始化完成、标签切换、主题切换和系统主题变化导致重新渲染时同步当前样式。
- 页面组件不直接调用窗口 API；隐私页沿用设置页所属标签的系统栏样式。

## 状态与失败处理

- 首次内容加载前先使用系统主题对应的基础样式，设置读取完成后同步用户保存的最终主题和当前标签。
- 系统栏设置失败不阻断内容加载，也不引入新的用户提示；后续标签或主题变化会再次尝试同步。
- 不修改应用包名、签名、权限、版本或发布状态。

## 测试与验收

- Hypium 单元测试先覆盖浅色首页、浅色非首页和深色主题的颜色及图标模式映射，并先观察失败。
- 执行项目静态检查、完整 Hypium、debug/ohosTest/release 构建。
- 在可用 phone 设备上逐一查看首页、统计、设置、隐私页及浅/深/跟随系统切换；确认上下系统栏无白色断层且内容未进入系统栏。
- tablet、2in1 仅在有可用目标时做运行验证，否则按项目既有规则记录为 `blocked`。
